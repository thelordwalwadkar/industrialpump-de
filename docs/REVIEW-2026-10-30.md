# Full review — build vs. the real objective (30 Oct 2026)

**Objective (as restated by the client):** replicate industrialpumps.nl for Germany (industrialpumpgroup.de), **page by page, no page missed**, content copied and translated, design may differ a little. **Skip the webshop.** Very SEO-friendly. **All schemas from the first prompt, integrated into Storyblok.**

**Evidence used:** the first prompt (MEGA PROMPT v3.0) · the Screaming Frog crawl of industrialpumps.nl (1,244 URLs) · the live site (sitemap, robots, JSON-LD, hreflang, headings of one page per type) · the client's own `industrialpumps_schema_map.csv` · every file in this repository · live checks of the published repo and GitHub Pages link.

## 1. Verdict in one paragraph
What exists is a **strong technical foundation** (14 templates, Storyblok content model, schema builders + validators, design, CI/Docker, a working public test link) but only **about 6 % of the pages the objective requires**. It was built against an earlier, narrower instruction ("no mass pages, one sample product per series") and against the domain `industrialpump.de`. Measured against the objective above it is **not done**; the foundation can carry the rest, but roughly 160 pages, three new templates, an English/German language decision and the Storyblok go-live are still open.

## 5. What is good and should be kept
- Folder = URL = breadcrumb from one source; auto-hiding links to pages that do not exist yet, so adding pages never breaks navigation.
- Schema built from the same data as the visible page and checked against it (breadcrumb, article number, FAQ, `@id` resolution); placeholders never leak into schema.
- Automatic gates on every build (JSON-LD, links, orphans, titles/descriptions, English-text scan) and in CI.
- Design tokens from three client colours with contrast gates; IPG-style design; mobile-safe.
- The public test link works (checked: HTTP 200 on home and a deep page) and is `noindex`.

## 6. Plan to meet the objective
1. **Decisions** (section 7) — one short reply.
2. **Extract** each of the 174 live pages into structured blocks (headings, paragraphs, lists, tables, FAQ, forms, images, internal links) with a script; keep the crawl's link graph for internal linking.
3. **New templates:** Job (`JobPosting`), About (`AboutPage`), FAQ (`FAQPage`); upgrade Topic/Segment/Application/Type to the schema map; add FAQ+Service to Home and Hubs.
4. **Translate** in batches by section (pumpentypen → branchen/anwendungen → revision → marken → pumpenschule/wissen → news/cases/karriere → company/legal), with the glossary, German titles/meta written fresh for search intent, not translated.
5. **Storyblok:** generate stories for all pages, push, seed, test the preview bridge on a real space.
6. **SEO layer:** hreflang, `og:image`, alt texts, `lastmod`, German keyword map using the existing keyword workbooks, redirects stub, robots/sitemap for the real domain.
7. **QA:** rerun all gates on ~175 pages, Lighthouse, native-speaker review list, client sign-off list for claims.
Size: ~140,000 words to translate and ~175 stories. Because of plan limits this should run in **7 batches over several sessions**, not in one go.
